# Contributing to AMR-X

## Branch Naming

- `feature/short-description` - New features
- `docs/short-description` - Documentation updates
- `fix/short-description` - Bug fixes

## Commit Messages

Keep commits small and focused. Examples:

- `update market study structure`
- `document dashboard stack`
- `add electrical safety questions`

## Pull Request Rules

- Link the related GitHub issue
- Explain the change and why it matters
- Keep PRs small and focused
- Request review before merging

## Documentation Rules

- No unsourced claims or fake data
- Use `TBD` for undecided items
- Keep files organized by topic
- Add blank lines before and after headings
- End every file with a newline
- Use exactly one `#` title per markdown file

## Agent Rules

Agents working on this project must read `.agents.md` before editing.

## General Principles

- Review documentation changes carefully
- Do not mix unrelated changes in one PR
- Update decision logs when technical choices change
- Keep prose compact and professional
